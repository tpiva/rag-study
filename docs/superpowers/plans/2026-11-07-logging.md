# Plano de Implementação: logging no lugar de print

> **Para agentes:** SUB-SKILL OBRIGATÓRIA: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para implementar este plano tarefa por tarefa. Os passos usam checkbox (`- [ ]`) para acompanhamento.

**Objetivo:** Substituir todo `print` em `src/rag_study/` pelo módulo padrão `logging`, configurado uma única vez por ponto de entrada e sempre escrevendo em stderr.

**Arquitetura:** Um pequeno `logging_config.py` expõe `setup_logging(level)`, chamado apenas pelos dois pontos de entrada (`ingest.main` e `mcp_server.main`). Todos os outros módulos só fazem `logger = logging.getLogger(__name__)` e registram mensagens; nunca configuram handlers. O nível vem da nova variável de ambiente `RAG_LOG_LEVEL`, lida pelo `Config`.

**Stack:** `logging` da stdlib do Python, `caplog` do pytest.

**Spec:** nenhuma — pedido feito na conversa ("adicionar logging ao invés de print"). Pontos com `print` hoje: `loader.py` (aviso de arquivo pulado), `ingest.py` (aviso de pasta vazia e resumo final), `mcp_server.py` `main()` (duas mensagens de inicialização em stderr). O `print("Hello from rag-study!")` de `__init__.main()` é scaffold e fica fora do escopo.

## Restrições Globais

- Logs vão **somente para stderr**. O servidor MCP fala o protocolo pelo stdout; qualquer escrita ali corrompe a comunicação.
- Módulos de biblioteca (`loader`, `chunking`, `indexing`, `search`, `config`) nunca chamam `basicConfig` nem adicionam handlers.
- O nome do logger é sempre `logging.getLogger(__name__)`.
- As mensagens continuam em inglês (todo texto do código foi traduzido para inglês).
- Formato do log: `%(asctime)s %(levelname)s %(name)s: %(message)s`. Os prefixos antigos `[warning]` / `[rag-study]` saem — nível e nome do logger os substituem.
- Nível padrão `INFO`; configurável via `RAG_LOG_LEVEL`.

## Pontos de Atenção na Revisão

- `RAG_LOG_LEVEL` inválido (ex.: `"banana"`): deve cair para `INFO`, sem derrubar o servidor MCP na inicialização.
- `setup_logging` chamado duas vezes (os testes chamam `main()` várias vezes): não pode empilhar handlers duplicados.
- Qualquer escrita em stdout no processo do servidor MCP: um handler em stdout quebraria o protocolo; o teste garante que o stream do handler é `sys.stderr`.
- Nível em minúsculas (`RAG_LOG_LEVEL=debug`): deve funcionar.
- Ingestão de pasta vazia: continua retornando `0` e agora registra em WARNING, não INFO.
